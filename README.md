# WorkoutLog

**WorkoutLog** — мобильное приложение-дневник для силовых тренировок, созданное на **Flutter** с использованием **Firebase**.

Приложение помогает пользователю вести учёт упражнений, подходов, рабочих весов, истории тренировок и прогресса. Также приложение даёт рекомендацию по следующему рабочему весу на основе прошлой тренировки.

---

## Описание проекта

WorkoutLog предназначен для людей, которые занимаются силовыми тренировками и хотят отслеживать свой прогресс.

Пользователь может создать упражнение, например:

```text
Жим лёжа
80 кг
3 подхода по 8 повторений
```

После завершения тренировки приложение сохраняет результат и на следующей тренировке предлагает новый рабочий вес:

```text
В прошлый раз: 80 кг × 8
Попробуй сегодня: 82.5 кг × 8
```

Если пользователь не смог выполнить подход, тренировка сохраняется как неполная, а приложение не увеличивает вес и предлагает повторить прошлый результат.

## Основной функционал

### Авторизация

В приложении реализованы:

* регистрация пользователя;
* вход в аккаунт;
* выход из аккаунта;
* восстановление пароля через email;
* сохранение сессии через функцию «запомнить меня»;
* обработка ошибок входа и регистрации.

При регистрации пользователь указывает:

* имя;
* email;
* телефон;
* дату рождения;
* текущий вес;
* целевой вес;
* процент жира;
* цель тренировок;
* количество тренировок в неделю;
* пароль.

Телефон должен начинаться с `+7`.

---

### Главный экран тренировки

На главном экране отображается выбранное упражнение, текущий подход и список всех подходов.

Статусы подходов:

* зелёный — подход завершён;
* жёлтый — подход выполняется;
* серый — подход ещё не начат.

На главном экране есть:

* кнопка начала подхода;
* кнопка завершения подхода;
* кнопка «Не получилось» для неполного выполнения;
* кнопка отдыха;
* выбор упражнения;
* добавление нового упражнения;
* умная рекомендация следующего рабочего веса.

Логика тренировки:

1. Сначала приложение показывает состояние «Готов к подходу».
2. Пользователь нажимает «Начать подход».
3. Подход переходит в состояние выполнения.
4. Пользователь может завершить подход или отметить, что подход не получился.
5. После выполнения всех подходов тренировка сохраняется в историю.
6. Приложение предлагает следующий рабочий вес.

---

### Умная рекомендация веса

Приложение анализирует последнюю тренировку по выбранному упражнению.

Если пользователь выполнил все подходы:

```text
следующий вес = прошлый вес + 2.5 кг
```

Если пользователь не выполнил подход:

```text
следующий вес = прошлый вес
```

Пример:

```text
Прошлая тренировка:
Жим лёжа — 90 кг × 8, 3/3 подхода

Следующая рекомендация:
92.5 кг × 8
```

Пример неполной тренировки:

```text
Прошлая тренировка:
Жим лёжа — 90 кг × 8, 1/3 подхода

Следующая рекомендация:
90 кг × 8
```

---

### Таймер отдыха

В приложении есть отдельный экран отдыха.

На экране отдыха отображается:

* выбранное упражнение;
* текущий подход;
* таймер отдыха;
* список подходов;
* кнопка завершения отдыха.

---

### Добавление упражнения

Пользователь может добавить новое упражнение и указать:

* название упражнения;
* рабочий вес;
* количество повторений;
* количество подходов.

После добавления упражнение сохраняется и появляется в списке выбора упражнений.

---

### Выбор упражнения

Пользователь может выбрать упражнение из библиотеки созданных упражнений.

Для каждого упражнения отображается:

* название;
* рабочий вес;
* количество повторений;
* количество подходов.

---

### История тренировок

В разделе истории отображается прогресс по выбранному упражнению.

Экран истории включает:

* название выбранного упражнения;
* график изменения рабочего веса;
* текущий рабочий вес;
* рекомендуемый следующий вес;
* количество тренировок;
* прогресс по тренировкам за неделю;
* список последних тренировок;
* следующую цель по весу.

История помогает пользователю видеть, как меняется его рабочий вес с течением времени.

---

### Профиль пользователя

В профиле пользователь может просматривать и редактировать свои данные:

* имя;
* телефон;
* дата рождения;
* цель тренировок;
* текущий вес;
* целевой вес;
* процент жира;
* количество тренировок в неделю.

Также профиль показывает:

* количество сохранённых тренировок;
* цель тренировок;
* текущий вес;
* целевой вес;
* процент жира;
* прогресс тренировок за неделю.

---

### Push-уведомления

В приложении подключены Firebase Cloud Messaging уведомления.

Реализовано:

* запрос разрешения на уведомления;
* получение FCM-токена устройства;
* сохранение FCM-токена в Firestore;
* подписка пользователя на topic `workoutlog_updates`;
* получение push-уведомлений;
* отображение уведомления внутри приложения, если приложение открыто.

Пример уведомления:

```text
WorkoutLog
Пора на тренировку! Открой приложение и продолжи прогресс 💪
```

## Firebase

В приложении используется Firebase.

### Firebase Authentication

Используется для:

* регистрации пользователя;
* входа в аккаунт;
* выхода из аккаунта;
* восстановления пароля;
* получения email и имени пользователя.

### Cloud Firestore

Используется для хранения:

* профиля пользователя;
* созданных упражнений;
* истории тренировок;
* рабочих весов;
* рекомендаций следующего веса;
* FCM-токена устройства.

Примерная структура базы данных:

```text
users/
└── userId/
    ├── name
    ├── email
    ├── phone
    ├── birthDate
    ├── goal
    ├── currentWeight
    ├── targetWeight
    ├── bodyFat
    ├── weeklyWorkoutsGoal
    ├── workoutsDone
    ├── fcmToken
    ├── notificationsEnabled
    │
    ├── exercises/
    │   └── exerciseId/
    │       ├── name
    │       ├── weight
    │       ├── reps
    │       └── sets
    │
    └── workout_logs/
        └── logId/
            ├── exerciseId
            ├── exerciseName
            ├── weight
            ├── reps
            ├── sets
            ├── setsCompleted
            ├── recommendedNextWeight
            └── createdAt
```

### Firebase Cloud Messaging

Используется для push-уведомлений.

Приложение подписывает пользователя на topic:

```text
workoutlog_updates
```

## Настройка Firebase

Для корректной работы Firebase нужно:

1. Создать проект в Firebase Console.
2. Подключить Android-приложение.
3. Скачать файл `google-services.json`.
4. Поместить его в папку:

```text
android/app/google-services.json
```

5. Убедиться, что в проекте есть файл:

```text
lib/firebase_options.dart
```

Он создаётся с помощью FlutterFire CLI.

---

## Важно про `google-services.json`

Файл:

```text
android/app/google-services.json
```

содержит настройки Firebase-проекта.

Если репозиторий публичный, этот файл лучше не загружать в GitHub.
Он должен быть добавлен в `.gitignore`:

```gitignore
android/app/google-services.json
```

После клонирования проекта другой пользователь должен добавить свой `google-services.json` вручную.
